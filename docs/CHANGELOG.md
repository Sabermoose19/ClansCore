# 1.2.0

- Retire ClansChat as a formatter; only api/core are active build modules. Keep previous source/JAR locally under retired, outside the current distribution.
- Core optionally registers %clanscore_name%, %clanscore_stars%, %clanscore_chatprefix% through PlaceholderAPI. Ordinary lookups use immutable cached membership, with empty output when unclanned.
- Add a small LPC Paper-renderer adapter for per-viewer clan colours. Exact %clanname% spelling is supported in LPC as combined stars/name/space; it is not a native PAPI expansion token. LPC retains full layout and LuckPerms ownership.
- Shield message content from token substitution; preserve audiences/cancellation and use thread-local nested event scopes for deferred PAPI fields. No private chat is added.
- LPC was not built, installed, run or tested, at the user's explicit request. Integration test sources compile but are excluded by default. Only 33 existing Core tests ran. Do not equate compilation with runtime compatibility.
- Stop, replace ClansCore.jar, remove ClansChat.jar and restart. Optional hook switches require restart. No clan-data migration.

# 1.1.0

- Remove private-chat permission nodes and wildcard attachments. Old `private` config sections and channel-only system messages are cleaned up during startup/reload; public formats, colours, messages and LuckPerms overrides are preserved.
- Install both matching JARs and perform a full restart. Existing clan data needs no migration. Old permissions stored in LuckPerms have no effect and may be removed by the operator.

# 1.0.3

- Root commands now declare native command permissions, so the server can omit inaccessible roots (including their plugin-namespaced forms) from the client's command list.
- `/clanadmin` allows the root when any effective staff leaf permission is granted, preserving delegated staff access without requiring an all-admin wildcard. `/clan` follows normal player leaf permissions and registered extension permissions. `/cc` and `/clanschat` use their existing exact command nodes.
- Normal subcommand suggestions also enforce clan membership/rank. Peace response suggestions check the corresponding permission separately. Chat provides explicit completion instead of falling back to online player names.
- Extension registration/removal updates the `/clan` root permission and refreshes connected players' command trees through their entity schedulers. No new permission nodes or database/config migration.
- Replace both JARs and restart. If permission changes leave stale suggestions in a client, reconnect to obtain a fresh command tree. OPs and users with effective admin permissions correctly continue to see staff commands.

# 1.0.1

- Developer API JAR moved under `dist/developer/` so the top-level release JARs are the two installable plugins.
